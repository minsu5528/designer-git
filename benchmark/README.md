## 벤치마크 요약

> Git LFS는 바이너리 파일이 조금만 수정되어도 파일 전체가 새 객체로 저장되는 구조입니다.  
> designer-git Delta 엔진은 변경된 일부 블록만 저장하는 방식을 사용합니다.  
> 아래 수치는 Git LFS 실험 결과와 designer-git Delta 엔진 실험 결과를 요약한 비교입니다.

| 비교 항목 | Git LFS | designer-git Delta 엔진 |
|---|---:|---:|
| 저장 방식 | 수정된 파일 전체 저장 | 변경된 Delta 블록만 저장 |
| 100MB급 파일 1바이트 수정 시 저장 증가량 | 약 100MB | 120KB |
| 1GB급 파일 1바이트 수정 시 저장 증가량 | 약 1GB | 827KB |
| 10GB급 파일 1바이트 수정 시 저장 증가량 | 약 10GB | 8,372KB |
| 저장 공간 절감률 | 0% 수준, 전체 파일 재저장 | 약 99.88% ~ 99.92% |
| 평균 Git LFS add + commit 시간 | 약 5.09초 / 회 | 해당 없음 |
| Delta 생성 시간 | 해당 없음 | 100MB: 3.5초 / 1GB: 45.3초 / 10GB: 390초 |
| 복원 시간 | 해당 없음 | 100MB: 0.15초 / 1GB: 1.4초 / 10GB: 56.9초 |

### 결론

Git LFS는 대용량 바이너리 파일에서 작은 수정이 발생해도 파일 전체를 다시 저장하기 때문에, 커밋이 반복될수록 저장소 용량이 파일 크기 단위로 증가합니다.

반면 designer-git Delta 엔진은 변경된 부분만 Delta 데이터로 저장하기 때문에, 100MB~10GB급 파일 기준 약 99.9% 수준의 저장 공간 절감 효과를 확인할 수 있었습니다.
