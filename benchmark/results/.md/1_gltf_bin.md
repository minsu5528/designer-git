# 실험 1 케이스 B, C: 후반 파이프라인 직렬화 비교 (Blender glTF .bin 기준)

## 1. 실험 개요

본 실험은 실험 1의 케이스 B(씬 어셈블리), 케이스 C(애니메이션 키프레임 수정)를 Blender glTF .bin 파일로 진행한 실험이다. FBX(Maya)는 매 export마다 전체 재직렬화가 발생하여 delta 효율이 없는 것으로 확인되어, Blender에서 glTF 분리 형식으로 내보낸 .bin 파일로 실험을 대체하였다. glTF 포맷은 씬 구조와 재질 정보를 담은 JSON 텍스트(.gltf)와 실제 메시 데이터를 담은 바이너리(.bin) 두 파일이 세트로 구성된다. .gltf(텍스트)는 git도 처리할 수 있는 포맷이므로, git이 못 다루는 바이너리 파일에서 delta 효율을 증명하기 위해 .bin 파일을 실험 대상으로 설정했다.

실험은 각 케이스마다 새 저장소를 생성한 뒤 다음 구조로 진행했다.

```text
character_base.bin → character_scene_v2.bin  (케이스 B: 씬 어셈블리)
character_base.bin → character_anim_v2.bin   (케이스 C: 애니메이션 키프레임 수정)
```

## 5. 케이스별 결과 해석

### 5.1 케이스 B (씬 어셈블리)

케이스 B는 오브젝트를 X축으로 100 이동하는 씬 어셈블리 작업이다. glTF 내보내기 기본 설정 기준으로 Transform 값은 .gltf JSON에만 기록되고 .bin의 버텍스 데이터는 실질적으로 변경되지 않는다. 20K의 소량 delta가 발생했으며, 전체 18MB 대비 극소량이어서 delta 효율이 매우 높게 나타났다.

| 항목       |    값 |
| ---------- | ----: |
| 원본 크기  |  18MB |
| delta 크기 |   20K |
| 변경률     | 0.11% |
| 절감률     | 99.9% |

### 5.2 케이스 C (애니메이션 키프레임 수정)

케이스 C는 30프레임에서 본의 회전값을 수정하고 키프레임을 삽입하는 애니메이션 작업이다. glTF 포맷에서 애니메이션 키프레임 데이터(타임스탬프, 회전값 등)는 .bin 파일에 저장된다. 케이스 B 대비 delta 크기가 다소 크게 나타났으나 전체 파일 대비 변경량이 극소량이어서 높은 delta 효율이 유지되었다.

| 항목       |    값 |
| ---------- | ----: |
| 원본 크기  |  18MB |
| delta 크기 |   32K |
| 변경률     | 0.18% |
| 절감률     | 99.8% |

## 6. 주요 관찰

### 6.1 .bin 파일과 .gltf 파일의 역할 분리

glTF 포맷에서 씬 어셈블리(Transform 수정) 작업은 .gltf(JSON 텍스트)에만 변경이 발생하고 .bin(바이너리 데이터)은 변경되지 않는다. 반면 애니메이션 키프레임 데이터(타임스탬프, 회전값 등)는 .bin 파일에 저장되므로 키프레임 삽입 시 .bin에도 소량의 변경이 발생한다. 두 케이스 모두 변경량이 전체 파일 대비 극소량이어서 .bin 기준 변경률이 매우 낮게 나타났다.

### 6.2 FBX와의 비교

FBX(Maya)는 매 export마다 전체 재직렬화가 발생하여 변경률 100%로 delta 효율이 없었다. 반면 glTF .bin은 같은 후반 파이프라인 작업에서 변경률 0.11~0.18%로 매우 높은 delta 효율을 보였다. 이는 포맷 구조가 delta 효율에 직접적인 영향을 미친다는 것을 보여준다.

### 6.3 실험 과정에서 발견된 사항

- FBX 파일을 Blender에서 glTF로 변환 시 캐릭터 메시가 뭉개지는 현상이 발생했다.
- .gltf(텍스트) 파일로 실험 시 파일 크기 변화로 인해 정확한 delta 측정이 어려웠다. 실제 바이너리 메시 데이터인 .bin 파일을 실험 대상으로 설정하는 것이 적합하다.

## 7. 결론

실험 1 케이스 B, C 결과, Blender glTF .bin 파일에서 씬 어셈블리와 애니메이션 키프레임 수정 작업 모두 99% 이상의 delta 절감률을 보였다. 씬 어셈블리는 Transform 값이 .gltf에만 기록되어 .bin 변경이 없었고, 애니메이션 키프레임은 .bin에 소량의 데이터가 추가되었으나 전체 파일 대비 극소량이었다. dgit은 18MB 크기의 바이너리 메시 파일에서 변경된 부분만 추출하여 20K~32K의 delta로 저장함으로써 목표치 90% 절감을 크게 초과하는 결과를 달성했다.
