# 실험 4: 수정량별 dgit delta 효율 분석

## 1. 실험 개요

본 실험은 비압축 TIFF 텍스처 파일에서 수정량이 증가할수록 dgit의 delta 저장 효율이 어떻게 변하는지 확인하기 위한 실험이다. 기준 파일 `tex_v1_uncompressed.tif`에서 각 수정 케이스를 독립적으로 비교했으며, 동일 실험을 3회 반복하여 평균값을 산출했다.

실험은 누적 커밋 방식이 아니라, 각 케이스마다 새 저장소를 생성한 뒤 다음 구조로 진행했다.

```text
v1_base → caseA_tiny
v1_base → caseB_uv_small
v1_base → caseC_medium
v1_base → caseD_full
```

이 방식은 A, B, C, D가 서로 이어지는 변경이 아니라, 모두 동일한 기준 파일 `v1`과 직접 비교되도록 하기 위한 것이다.

## 6. case별 결과 해석

### 6.1 caseA_tiny

caseA는 4MB 기준 변경 블록이 2/25개로 매우 적었다. 3회 반복 모두 delta로 저장되었으며, delta 크기는 매번 99,122 bytes로 동일했다.

| 항목 | 값 |
|---|---:|
| 변경 블록 | 2/25 |
| 변경 블록 비율 | 8.00% |
| 저장 방식 | delta, 3회 모두 동일 |
| 평균 저장 크기 | 99,122 bytes, 약 0.10 MB |
| 평균 절감률 | 99.90% |

caseA는 극소량 수정에서 dgit이 매우 높은 저장 효율을 보인다는 것을 확인하는 기준 케이스로 사용할 수 있다.

### 6.2 caseB_uv_small

기존 caseB는 3D 뷰에서는 얼굴 중심의 소량 수정처럼 보였지만, 실제 파일에서는 4MB 블록 기준 20/25개 블록이 변경되어 fullcopy로 전환되었다. 이에 따라 UV를 고려해 수정 영역을 다시 잡은 `caseB_uv_small`을 새로 만들었다.

`caseB_uv_small`은 변경 블록이 17/25개, 즉 68.00%로 측정되었다. 이는 dgit의 fullcopy 전환 기준인 80%보다 낮기 때문에, 3회 반복 모두 delta로 저장되었다.

| 항목 | 값 |
|---|---:|
| 변경 블록 | 17/25 |
| 변경 블록 비율 | 68.00% |
| 저장 방식 | delta, 3회 모두 동일 |
| 평균 delta 크기 | 37,575,225 bytes, 약 37.58 MB |
| 평균 절감률 | 62.68% |

이 결과는 UV를 고려해 수정 영역을 통제하면 fullcopy 전환을 피할 수 있음을 보여준다. 다만 3D 텍스처 작업 특성상 padding, dilation, projection, UV island 배치 때문에 변경 픽셀이 여러 블록에 분산될 수 있어, 소량 수정이라도 delta 크기가 상당히 커질 수 있다.

### 6.3 caseC_medium

caseC는 4MB 기준 변경 블록이 24/25개로 측정되었다. 이는 전체 블록의 96.00%에 해당하므로 dgit의 fullcopy 전환 조건을 넘는다.

| 항목 | 값 |
|---|---:|
| 변경 블록 | 24/25 |
| 변경 블록 비율 | 96.00% |
| 저장 방식 | fullcopy, 3회 모두 동일 |
| 평균 저장 크기 | 100,688,118 bytes, 약 100.69 MB |
| 평균 절감률 | 0.00% |

caseC는 중간 수정이지만 실제 파일 내부에서는 대부분의 4MB 블록에 변경이 발생했기 때문에 fullcopy로 저장되었다.

### 6.4 caseD_full

caseD는 25/25개 블록이 모두 변경된 것으로 측정되었다. 따라서 3회 반복 모두 fullcopy로 저장되었다.

| 항목 | 값 |

| 평균 저장 크기 | 100,688,118 bytes, 약 100.69 MB |
| 평균 절감률 | 0.00% |

caseD는 전체 수정 케이스로, dgit이 fullcopy로 전환되는 것이 정상적인 결과로 해석된다.

## 7. 주요 관찰

### 7.1 변경 블록 비율과 저장 방식의 관계

이번 실험에서는 dgit의 저장 방식이 변경 블록 비율과 강하게 연결되어 나타났다.

| case | 변경 블록 비율 | 저장 방식 |
|---|---:|---|
| `caseA_tiny` | 8.00% | delta |
| `caseB_uv_small` | 68.00% | delta |
| `caseC_medium` | 96.00% | fullcopy |
| `caseD_full` | 100.00% | fullcopy |

변경 블록 비율이 80% 미만인 caseA와 caseB_uv는 delta로 저장되었고, 80%를 넘는 caseC와 caseD는 fullcopy로 저장되었다. 따라서 현재 구현에서는 변경 블록 비율이 fullcopy 전환의 핵심 지표로 작동한다.

### 7.2 시각적 수정량과 파일 내부 변경량은 다를 수 있음

3D 텍스처 작업에서는 사용자가 3D 뷰에서 보는 수정 면적과 실제 2D TIFF 파일 내부의 변경 분포가 일치하지 않을 수 있다. 그 이유는 다음과 같다.

- 3D 표면은 UV island로 펼쳐져 2D 텍스처에 저장된다.
- 하나의 시각적 부위가 2D 텍스처에서는 여러 위치에 흩어져 있을 수 있다.
- 브러시 projection, padding, dilation, anti-aliasing 때문에 주변 픽셀도 함께 변경될 수 있다.
- UV island가 분산되어 있으면 작은 수정도 여러 4MB 블록에 걸쳐 저장될 수 있다.

따라서 dgit의 효율은 단순한 시각적 수정 면적보다, 변경 픽셀이 파일 내부에서 얼마나 넓게 분산되는지에 더 큰 영향을 받는다.

## 8. 결론

실험 4 결과, dgit은 극소량 수정에서는 매우 높은 delta 효율을 보였다. `caseA_tiny`는 평균 0.10MB의 delta만 생성되어 99.90%의 절감률을 보였다.

UV를 고려해 다시 만든 `caseB_uv_small`은 3회 모두 delta로 저장되었고, 평균 delta 크기는 37.58MB, 평균 절감률은 62.68%였다. 이는 수정 영역을 UV 기준으로 통제하면 fullcopy 전환을 피할 수 있음을 보여준다. 그러나 변경 픽셀이 17/25개 블록에 분산되어 delta 크기는 여전히 크게 나타났다.

`caseC_medium`과 `caseD_full`은 각각 96.00%, 100.00%의 변경 블록 비율을 보여 3회 모두 fullcopy로 전환되었다. 두 케이스의 절감률은 0.00%였다.

따라서 본 실험은 dgit이 비압축 TIFF의 작은 수정에는 효과적이지만, 3D 텍스처 특유의 UV 분산과 블록 단위 변경률 증가가 발생하면 fullcopy 전환 또는 delta 크기 증가가 발생할 수 있음을 보여준다. 즉, 수정 면적 자체보다 **파일 내부 변경 분산도**가 dgit의 delta 효율을 결정하는 중요한 변인이다.

## 9. 보고서용 요약 문장

실험 4에서는 수정량 증가에 따른 dgit의 delta 효율 변화를 3회 반복 측정했다. 극소량 수정인 caseA는 4MB 기준 2/25개 블록만 변경되어 평균 99.90%의 절감률을 보였다. UV를 고려해 다시 만든 소량 수정 caseB_uv는 17/25개 블록이 변경되었으나 fullcopy 임계치 아래에 있어 3회 모두 delta로 저장되었고, 평균 62.68%의 절감률을 보였다. 반면 caseC와 caseD는 각각 24/25개, 25/25개 블록이 변경되어 모두 fullcopy로 전환되었다. 이 결과는 3D 텍스처 작업에서 시각적 수정 면적보다 UV island, padding, projection 등으로 인해 변경 픽셀이 파일 내부에 얼마나 분산되는지가 dgit의 저장 효율에 더 직접적인 영향을 준다는 점을 보여준다.
