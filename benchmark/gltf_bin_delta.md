# 실험 2: 파이프라인 단계별 delta 효율 (glTF .bin 기준)

## 1. 실험 개요

본 실험은 glTF 포맷의 바이너리 메시 파일(.bin)에서 파이프라인 단계별 작업 후 dgit의 delta 저장 효율을 측정한 실험이다. glTF 포맷은 씬 구조와 재질 정보를 담은 JSON 텍스트(.gltf)와 실제 메시 데이터를 담은 바이너리(.bin) 두 파일이 세트로 구성된다. .gltf(텍스트)는 git도 처리할 수 있는 포맷이므로, git이 못 다루는 바이너리 파일에서 delta 효율을 증명하기 위해 .bin 파일을 실험 대상으로 설정했다.

실험은 각 케이스마다 새 저장소를 생성한 뒤 다음 구조로 진행했다.

```text
character_base.bin → character_scene_v2.bin  (케이스 B: 씬 어셈블리)
character_base.bin → character_anim_v2.bin   (케이스 C: 애니메이션 키프레임 수정)
```

## 2. 실험 환경 및 입력 파일

| 항목           | 내용                                                           |
| -------------- | -------------------------------------------------------------- |
| 실행 경로      | `~/experiment`                                                 |
| 기준 파일      | `character_base.bin`                                           |
| 파일 형식      | glTF 바이너리 메시 파일 (.bin)                                 |
| 기준 파일 크기 | 약 18MB                                                        |
| 비교 방식      | 각 케이스별 독립 dgit 저장소 생성 후 `base → case` 커밋        |
| 측정 명령어    | `du -sh .vcs/objects/deltas/`                                  |
| 측정값         | delta 저장 크기, 변경률, 절감률                                |
| 원본 파일 경로 | `character_base.fbx` → Blender에서 glTF 분리 형식으로 내보내기 |

## 3. 케이스 정의

| case                                | 설명                         | 작업 내용                                                                       |
| ----------------------------------- | ---------------------------- | ------------------------------------------------------------------------------- |
| 케이스 B (씬 어셈블리)              | 오브젝트 위치 변경           | Blender에서 오브젝트 선택 → G키 → X키 → 100 입력 → Enter (X축 100 이동)         |
| 케이스 C (애니메이션 키프레임 수정) | 키프레임 삽입 및 회전값 수정 | 포즈 모드에서 본 선택 → 30프레임 이동 → R키로 회전값 수정 → I키로 키프레임 삽입 |

## 5. 케이스별 결과 해석

### 5.1 케이스 B (씬 어셈블리)

케이스 B는 오브젝트를 X축으로 100 이동하는 씬 어셈블리 작업이다. Transform 값만 변경되는 작업으로, 실제 메시 데이터(.bin)는 변경되지 않는다. .gltf 파일에 Transform 값이 수정되었으나 .bin 파일의 버텍스 데이터는 그대로 유지되어 delta 효율이 매우 높게 나타났다.

| 항목       |    값 |
| ---------- | ----: |
| 원본 크기  |  18MB |
| delta 크기 |   20K |
| 변경률     | 0.11% |
| 절감률     | 99.9% |

### 5.2 케이스 C (애니메이션 키프레임 수정)

케이스 C는 30프레임에서 본의 회전값을 수정하고 키프레임을 삽입하는 애니메이션 작업이다. AnimationCurve 데이터가 .gltf에 추가되었으나 .bin의 메시 데이터는 변경되지 않아 높은 delta 효율이 유지되었다. 케이스 B 대비 delta 크기가 다소 크게 나타난 것은 키프레임 데이터가 추가되어 .gltf 구조에 변화가 생긴 영향으로 추측된다.

| 항목       |    값 |
| ---------- | ----: |
| 원본 크기  |  18MB |
| delta 크기 |   32K |
| 변경률     | 0.18% |
| 절감률     | 99.8% |

## 6. 주요 관찰

### 6.1 .bin 파일과 .gltf 파일의 역할 분리

glTF 포맷에서 씬 어셈블리, 애니메이션 키프레임 수정 등의 후반 파이프라인 작업은 .gltf(JSON 텍스트)에만 변경이 발생하고 .bin(바이너리 메시 데이터)은 변경되지 않는다. 따라서 .bin 기준 변경률이 매우 낮게 나타났다.

### 6.2 FBX와의 비교

FBX(Maya)는 매 export마다 전체 재직렬화가 발생하여 변경률 100%로 delta 효율이 없었다. 반면 glTF .bin은 같은 후반 파이프라인 작업에서 변경률 0.11~0.18%로 매우 높은 delta 효율을 보였다. 이는 포맷 구조가 delta 효율에 직접적인 영향을 미친다는 것을 보여준다.

### 6.3 실험 과정에서 발견된 사항

- FBX 파일을 Blender에서 glTF로 변환 시 캐릭터 메시가 뭉개지는 현상이 발생했다. FBX와 glTF 간 포맷 호환성 문제로 추측된다.
- .gltf(텍스트) 파일로 실험 시 파일 크기 변화로 인해 정확한 delta 측정이 어려웠다. 실제 바이너리 메시 데이터인 .bin 파일을 실험 대상으로 설정하는 것이 적합하다.

## 7. 결론

실험 2 결과, glTF .bin 파일에서 씬 어셈블리와 애니메이션 키프레임 수정 작업 모두 99% 이상의 delta 절감률을 보였다. 이는 후반 파이프라인 작업에서 메시 데이터(.bin)가 변경되지 않고 씬 구조 데이터(.gltf)만 변경되는 glTF 포맷의 특성에 기인한다. dgit은 18MB 크기의 바이너리 메시 파일에서 변경된 부분만 추출하여 20K~32K의 delta로 저장함으로써 목표치 90% 절감을 크게 초과하는 결과를 달성했다.
