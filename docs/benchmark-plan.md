# 벤치마크 실험 설계 문서

## 1. 실험 목적

designer_git의 핵심 가설을 수치로 검증한다.

> _"실제 3D·VFX 파이프라인 후반 작업에서 CDC delta 저장이 얼마나 효과적인가?  
> 그리고 어떤 조건에서 한계가 발생하는가?"_

초기 스컬핑/모델링 단계는 Vertex Buffer가 전체 재생성되므로 delta 효율이 낮다.  
텍스처링 이후 후반 단계(In-place 픽셀 수정, 키프레임 값 변경, Transform 수정)는 delta 효율이 높을 것으로 예측한다.  
**파이프라인 단계별 절감률 / commit 시간 / checkout 시간** 세 가지 지표를 객관적으로 측정하고, 그 결과를 CSV와 그래프로 산출한다.

---

## 2. 실험 설계

### 독립변수 (Independent Variables)

| 변수            | 값                                                                                      |
| --------------- | --------------------------------------------------------------------------------------- |
| 파이프라인 단계 | 텍스처링 (실측 완료) / 씬 어셈블리·애니메이션 (실측 완료, glTF .bin 기준) / 리깅 (예정) |
| 사용 툴         | Substance 3D Painter (텍스처링) / Blender (씬 어셈블리·애니메이션)                      |
| 수정량          | 극소(~8%) / 소량(~68%) / 중간(~96%) / 전체(~100%)                                       |

### 종속변수 (Dependent Variables)

- 저장소 증가량 (KB/MB)
- delta 크기 (KB)
- delta 효율 (절감률 %)
- commit 시간 (초)
- checkout 시간 (초)
- SHA256 검증 통과 여부
- Early-exit 판단 시간 (초)

### 비교군

| 군             | 설명                  |
| -------------- | --------------------- |
| 원본 전체 저장 | fullcopy baseline     |
| Git LFS        | 현재 업계 표준 대조군 |
| designer-git   | 본 프로젝트           |

### 반복 횟수: 3회 평균

### 실험 파일 구성

```
tex_v1_uncompressed.tif  ← 기준 텍스처 파일 (비압축 TIFF, 100.69 MB)
tex_v2~v10_uncompressed.tif  ← 수정 버전 (시나리오 3용)
character_base.bin  ← glTF 바이너리 메시 파일 (18MB, 시나리오 1용)
character_scene_v2.bin  ← 씬 어셈블리 수정본
character_anim_v2.bin  ← 애니메이션 키프레임 수정본
```

## 3. 시나리오별 실험 계획

### 시나리오 1 — Blender vs Maya 직렬화 비교 (한계 조건 탐색)

| 항목 | 내용                                                                         |
| ---- | ---------------------------------------------------------------------------- |
| 대상 | `character_base.fbx` / 100MB (동일 모델, 두 툴)                              |
| 핵심 | Maya(Autodesk 공식 FBX SDK) vs Blender(리버스 엔지니어링 구현)의 직렬화 차이 |
| 상태 | **케이스 A 완료 / 케이스 B·C glTF .bin으로 완료**                            |
| 담당 | 강민경                                                                       |

**[케이스 A] 폴리곤 편집 (초기 모델링 단계) — 실측 완료**

| 툴      | 변경률 | 판정       | 비고                             |
| ------- | ------ | ---------- | -------------------------------- |
| Maya    | 100%   | delta 불가 | 매 export마다 전체 재직렬화 확인 |
| Blender | ~100%  | delta 불가 | Vertex Buffer 재배치 확인        |

**[케이스 B] 씬 어셈블리 (후반 파이프라인) — glTF .bin으로 실측 완료**

> FBX는 Maya·Blender 모두 재직렬화 문제로 실험 불가 → Blender glTF .bin으로 대체

Blender 작업:

1. `character_base.gltf` 열기
2. 오브젝트 선택 → G키 → X키 → 100 입력 → Enter
3. File → Export → glTF 2.0 (glTF 분리) → `character_scene_v2` 저장

**실측 결과**

| 파일 기준 | 원본 크기 | delta 크기 | 변경률 | 절감률    |
| --------- | --------- | ---------- | ------ | --------- |
| .bin      | 18MB      | 20K        | 0.11%  | **99.9%** |

**[케이스 C] 애니메이션 키프레임 수정 (후반 파이프라인) — glTF .bin으로 실측 완료**

> FBX는 Maya·Blender 모두 재직렬화 문제로 실험 불가 → Blender glTF .bin으로 대체

Blender 작업:

1. `character_base.gltf` 열기
2. 포즈 모드 → 본 선택 → 30프레임 이동 → R키로 회전값 수정 → I키로 키프레임 삽입
3. File → Export → glTF 2.0 (glTF 분리) → `character_anim_v2` 저장

**실측 결과**

| 파일 기준 | 원본 크기 | delta 크기 | 변경률 | 절감률    |
| --------- | --------- | ---------- | ------ | --------- |
| .bin      | 18MB      | 32K        | 0.18%  | **99.8%** |

> glTF 포맷에서 애니메이션 키프레임 데이터(타임스탬프, 회전값)는 .bin에 저장되므로 씬 어셈블리보다 delta 크기가 다소 크게 나타났다.

### 시나리오 2 — 파이프라인 단계별 delta 효율 (핵심 증명)

| 항목     | 내용                                                               |
| -------- | ------------------------------------------------------------------ |
| 대상     | 각 단계별 파일 / Maya 실제 작업                                    |
| 목적     | 후반 파이프라인 각 단계에서 실제 현업 툴로 작업 후 delta 효율 실측 |
| 담당     | 강민경                                                             |
| 스크립트 | `scenario2_pipeline_efficiency.py`                                 |

**[2-1] 텍스처링 — Substance 3D Painter (실측 완료)**

> 비압축 TIFF 출력 필수: `텍스처 내보내기 → 파일 유형: tiff`  
> 압축 옵션 포함 시 delta 효율 0%로 하락

작업: 캐릭터 특정 부위 색상 수정 후 TIFF 비압축으로 내보내기  
측정: `tex_v1_uncompressed.tif → case 파일` delta 효율

**실측 결과 (3회 반복 평균, 4MB 블록 기준)**

| 수정 케이스            | 변경 블록 비율 | 저장 방식 | 저장 크기 | 절감률     |
| ---------------------- | -------------- | --------- | --------- | ---------- |
| A 극소량 (2/25 블록)   | 8.00%          | delta     | 0.10 MB   | **99.90%** |
| B UV 소량 (17/25 블록) | 68.00%         | delta     | 37.58 MB  | **62.68%** |
| C 중간 (24/25 블록)    | 96.00%         | fullcopy  | 100.69 MB | 0.00%      |
| D 전체 (25/25 블록)    | 100.00%        | fullcopy  | 100.69 MB | 0.00%      |

> **주의**: 3D 텍스처는 UV island 분산, padding, dilation 때문에 시각적 수정 면적과 실제 파일 내부 변경 분포가 일치하지 않는다. fullcopy 전환 기준은 변경 블록 비율 **80%**.

**[2-2] 리깅 / 애니메이션 / 씬 어셈블리**

Maya 툴 호환 문제로 실험 미진행.  
씬 어셈블리·애니메이션은 시나리오 1 케이스 B·C(Blender glTF .bin 기준)로 대체 실측 완료.

### 시나리오 3 — Git LFS vs designer-git 누적 저장소 비교 (실측 완료)

| 항목     | 내용                                                               |
| -------- | ------------------------------------------------------------------ |
| 대상     | `tex_v1~v10_uncompressed.tif` (비압축 TIFF, 100.69 MB) / 10회 커밋 |
| 목적     | 반복 커밋 시 누적 저장소 크기 차이를 수치와 그래프로 시각화        |
| 담당     | 강민경                                                             |
| 스크립트 | `scenario3_storage_comparison.py`                                  |

**실측 결과 (10회 커밋)**

| commit | Git LFS .git/lfs (MB) | dgit .vcs 전체 (MB) | dgit payload만 (MB) |
| -----: | --------------------: | ------------------: | ------------------: |
|      1 |                100.69 |              100.69 |              100.69 |
|      2 |                201.38 |              125.45 |              125.45 |
|      3 |                302.06 |              134.97 |              134.97 |
|      4 |                402.75 |              141.78 |              141.78 |
|      5 |                503.44 |              148.20 |              148.20 |
|      6 |                604.13 |              153.84 |              153.83 |
|      7 |                704.82 |              158.60 |              158.59 |
|      8 |                805.50 |              160.39 |              160.39 |
|      9 |                906.19 |              164.53 |              164.52 |
|     10 |              1,006.88 |              268.44 |              167.75 |

| 방식                           | 최종 크기   | Git LFS 대비 절감률 |
| ------------------------------ | ----------- | ------------------- |
| Git LFS                        | 1,006.88 MB | —                   |
| dgit payload (base + delta)    | 167.75 MB   | **83.34%**          |
| dgit .vcs 전체 (snapshot 포함) | 268.44 MB   | **73.34%**          |

> **snapshot 주의**: 10번째 커밋에서 dgit 스냅샷 정책에 의해 약 100.69 MB snapshot이 추가 생성되어 `.vcs` 전체 크기가 상승한다. 이는 delta 생성 실패가 아닌 복원 성능 최적화 비용이다.

### 시나리오 4 — 수정량별 delta 효율 임계치 탐색 (실측 완료)

| 항목     | 내용                                                      |
| -------- | --------------------------------------------------------- |
| 대상     | `tex_v1_uncompressed.tif` (100.69 MB, 비압축 TIFF)        |
| 목적     | 수정량이 얼마까지 증가해도 delta가 효율적인지 임계치 실측 |
| 담당     | 강민경                                                    |
| 스크립트 | `scenario4_threshold.py`                                  |

**실측 결과 (3회 반복 평균, 4MB 블록 기준)**

| 케이스    | 설명            | 변경 블록 비율 | 저장 방식 | 저장 크기 | 절감률     | commit 시간 |
| --------- | --------------- | -------------- | --------- | --------- | ---------- | ----------- |
| A 극소량  | 2/25 블록 변경  | 8.00%          | delta     | 0.10 MB   | **99.90%** | 3.220s      |
| B UV 소량 | 17/25 블록 변경 | 68.00%         | delta     | 37.58 MB  | **62.68%** | 1.823s      |
| C 중간    | 24/25 블록 변경 | 96.00%         | fullcopy  | 100.69 MB | 0.00%      | 1.068s      |
| D 전체    | 25/25 블록 변경 | 100.00%        | fullcopy  | 100.69 MB | 0.00%      | 1.593s      |

**fullcopy 전환 기준**: 변경 블록 비율 **80%** (실측 확인)

**핵심 관찰**:

- 시각적 수정 면적과 파일 내부 변경 분포는 일치하지 않는다. UV island 분산, padding, dilation, anti-aliasing 때문에 작은 수정도 여러 블록에 걸쳐 저장될 수 있다.
- 기존 caseB(3D 뷰 기준 얼굴 영역 수정)는 실제 20/25개 블록이 변경되어 fullcopy 전환됐다. UV 기준으로 수정 영역을 재조정한 `caseB_uv_small`은 17/25개 블록으로 delta 유지.
- dgit의 delta 효율을 결정하는 핵심 변인은 **시각적 수정 면적이 아닌 파일 내부 변경 분산도**다.

## 7. 스크립트 실행 방법

```bash
# 1. 프로젝트 WSL 홈으로 복사
cp -r /mnt/c/.../designer_git ~/designer_git

# 2. WSL에서 빌드
cd ~/designer_git
mkdir -p build && cd build
cmake .. && make -j4

# 3. 벤치마크 실행 (sudo 필요 — 파일 시스템 캐시 플러시용)
cd ~/designer_git
sudo python3 benchmark/measure.py --dgit ./build/dgit --scenarios 2,3,6,7,8
```
